# CLI shared DSL (interface root)

Interface: `cli` (the operator terminal end). This file holds the **cross-module** rows — sentence
patterns used identically by two or more CLI modules. Module-specific rows live in `{module}/dsl.md`.
Reading a feature merges this root with the feature's own module `dsl.md`; every step must match
**exactly one** row.

> The `cli` end is verified **end-to-end** (black-box): the E2E suite builds the `tellme` binary once
> and invokes it as a subprocess under a controlled environment, asserting exit code, stdout, stderr,
> and filesystem effects. Steps name only operator-facing surface (flags, env vars, paths).
>
> **Round 004** (`004-first-reasoning-turn`): the CLI now bears a network path — the prompt turn dials
> the configured provider. The `tellme performs no network access` row is therefore scoped to the
> **offline paths** (`--version`, `-d`, and a prompt-less boot); the prompt-bearing chat path is
> permitted egress.

## Given

| DSL Sentence | Gherkin Params | Data Table Params | Default Params | StepDef Implementation Semantics |
| --- | --- | --- | --- | --- |
| `the operator has a runnable tellme installation` | none | Not supported | `binary`: the E2E suite builds the `tellme` binary once per run and passes its path (e.g. `TELLME_BIN`). | `How`: assert the built binary exists and is executable. `State landing`: a runnable `tellme` binary is available for every scenario. `No-check`: no provider is contacted. |
| `the runtime home is "{home}"` | `home`: string; the operator-facing name of the runtime home (e.g. "ait-tmg"). | Not supported | `Actual path`: echo case uses a fresh empty temp directory to stand for `{home}`, exposed as `TELL_ME_HOME`. | `How`: create a fresh empty temp directory and set `TELL_ME_HOME` to it. `State landing`: `TELL_ME_HOME` is set in the process environment. `Write-back`: none (Arrange state only). |
| `the selected provider override is "{provider}"` | `provider`: string; the provider name supplied by the environment override. | Not supported | `Source`: arranged via `TELL_ME_SELECTED_PROVIDER`. | `How`: set `TELL_ME_SELECTED_PROVIDER` to `{provider}`. `State landing`: the effective selected provider is taken from the environment first (over the file's `SELECTED_PROVIDER`). `Write-back`: none. |
| `a well-formed configuration "{config_path}"` | `config_path`: string; the configuration path relative to the runtime home. | Not supported | `SELECTED_PROVIDER`: defaults to "deepseek-flash"; `PROVIDERS`: defaults to a single matching entry. | `How`: write a usable YAML file at `{home}/{config_path}` carrying `MODE`, `PERSON`, `SELECTED_PROVIDER`, and a `PROVIDERS` registry. `State landing`: the file exists and parses. `Write-back`: the configuration file. |
| `the session history already holds the exchanges:` | none | Supported (headers `prompt`, `answer`). | `Workspace`: writes into `$TELL_ME_HOME/output/<mode>/history.jsonl` (the effective mode's session workspace). | `How`: create the per-mode session workspace directory if absent, then write one JSON line per table row (`prompt`, `answer`) into `history.jsonl`, in table order. `State landing`: the session history file holds the arranged exchanges. `Write-back`: the session history file. |
| `the diagnostics are shown at a terminal` | none | Not supported | `Source`: arranged via the diagnostic environment seam `TELL_ME_FORCE_STDERR_TTY`. | `How`: set `TELL_ME_FORCE_STDERR_TTY` to `1` in the subprocess environment so tellme's **standard-error (`stderr`)** terminal probe reports the stream as a terminal (the round-019 interface-root row, shared by the `chat`, `diagnostics`, and `history` modules; mirroring the round-012 stdin seam). `State landing`: the effective `stderr` terminal probe reports a terminal. `Write-back`: none. |
| `the runtime home is not set` | none | Not supported | `Source`: the subprocess runs with `TELL_ME_HOME` unset/empty. | `How`: ensure `TELL_ME_HOME` is unset (or empty) in the subprocess environment. `State landing`: no runtime home is resolvable. `Write-back`: none. (Promoted to the interface root in round 026 — now shared by the `workspace` module, which asserts the exit-4 path, and the `chat` module, which asserts the `--tool-usage` report's `--version`-class footprint.) |
| `the effective mode is "{mode}"` | `mode`: string; the effective mode to arrange. | Not supported | `Source`: arranged via `TELL_ME_MODE` (environment over file). | `How`: set `TELL_ME_MODE` to `{mode}`. `State landing`: the effective mode resolves to `{mode}`. `Write-back`: none. (Round 085: **promoted** from `configuration/dsl.md` — the step is shared by the `configuration` and `history` modules, so its single authoritative row lives at the root.) |
| `a configured provider "{provider}" whose endpoint answers with "{answer}"` | `provider`: string; the selected provider key. `answer`: string; the answer text the endpoint returns. | Not supported | `config`: the default `$TELL_ME_HOME/configs/<effective mode>.yaml` with `SELECTED_PROVIDER` = `{provider}`; endpoint URL = the fake provider. | `How`: write a resolvable default configuration whose `SELECTED_PROVIDER` is `{provider}` and whose `PROVIDERS.{provider}.URL` points at the fake provider; script the fake to answer `{answer}`. `State landing`: the configuration is resolvable and the fake is ready to answer. `Write-back`: the configuration file + the fake's scripted response. (Round 085: **promoted** from `chat/dsl.md` — the step is shared by the `chat` and `history` modules, so its single authoritative row lives at the root.) |

## When

| DSL Sentence | Gherkin Params | Data Table Params | Default Params | StepDef Implementation Semantics |
| --- | --- | --- | --- | --- |
| `the operator starts tellme` | none | Not supported | `Config source`: no `-c` and **no prompt** — the boot path seeks the default `$TELL_ME_HOME/configs/<effective mode>.yaml`. | `How`: run the built `tellme` binary with no `-c` and no positional prompt, under the current environment (`TELL_ME_HOME` / `TELL_ME_MODE` / `TELL_ME_SELECTED_PROVIDER`). `State landing`: the process has run to completion. `Write-back`: captured exit code, stdout, stderr, and filesystem changes. |
| `the operator starts tellme pointing at the configuration "{config_path}"` | `config_path`: string; the configuration path relative to the runtime home. | Not supported | `Flags`: the run is invoked with `-c` pointing at `$TELL_ME_HOME/{config_path}`. | `How`: run `tellme -c $TELL_ME_HOME/{config_path}`. `State landing`: the process has run to completion. `Write-back`: captured exit code, stdout, stderr, and filesystem changes. |
| `the operator runs tellme with "{flag}"` | `flag`: string; a command-line flag with no other arguments (a terminal, prompt-less action such as `--version`, `-v`, `-h`, or `--help`). | Not supported | `Flags`: the run is invoked with `{flag}` alone. | `How`: run `tellme {flag}` (no `-c`, no positional prompt). `State landing`: the process has run to completion. `Write-back`: captured exit code, stdout, stderr. (Round 074: promoted to the interface root — shared by the `diagnostics` module (`--version`/`-v`) and the `usage` module (`-h`/`--help`).) |
| `the operator starts tellme with the prompt "{prompt}"` | `prompt`: string; the operator's prompt. | Not supported | `Flags`: no `-c`; the configuration is the default for the effective mode. | `How`: run `tellme "{prompt}"` under the current environment. `State landing`: the process has run to completion. `Write-back`: captured exit code, stdout, stderr, and the fake's recorded requests. (Round 085: **promoted** from `chat/dsl.md` — the step is shared by the `chat` and `history` modules, so its single authoritative row lives at the root.) |

## Then

| DSL Sentence | Gherkin Params | Data Table Params | Default Params | StepDef Implementation Semantics |
| --- | --- | --- | --- | --- |
| `tellme exits successfully` | none | Not supported | none | `Must-check`: `Presented Result`: the exit code equals the success code (0). `Should Not Happen`: no non-zero exit code. |
| `tellme refuses to proceed` | none | Not supported | none | `Must-check`: `Presented Result`: the exit code is non-zero (the run refused). `Should Not Happen`: the run must not be reported as success. |
| `tellme performs no network access` | none | Not supported | `Range`: the **offline paths** only — `-h`/`--help`, `-v`/`--version`, `-d`, `-l`, `-t`, a prompt-less `--new`, a **standalone `-b`/`--back [N]`** (round 081, ADR 0053), and a prompt-less boot (round 074 adds the help path). | `Must-check`: harness-mediated. `Presented Result` / `Authoritative State`: (i) a recording sink (the endpoint the configured provider points at) records **zero** connections across the offline paths; (ii) with egress blocked the offline paths' exit code and output are unchanged (differential witness). Round 004 **retired** the whole-binary capability guard ("no `net/http` in the closure" + no dialing symbol) because the prompt-bearing chat path legitimately links `net/http`; this is now an **offline-path behaviour** witness, not a whole-binary absence claim. `Should Not Happen`: an offline path must never dial the provider. |
| `tellme explains on stderr that "{reason}"` | `reason`: string; the **frozen class phrase** for a failure class (verbatim phrase). | Not supported | `Phrase vocabulary`: the eleven frozen class phrases — `the configuration could not be found`, `no configuration could be found`, `the configuration could not be parsed`, `the configuration is invalid` (a well-formed file whose resolved values fail validation — e.g. a negative rendered width, round 006), `the selected provider is not in the registry`, `the provider configuration is invalid`, `the provider request failed`, `the tool request failed` (a prompt run whose tool loop cannot complete — round 008), `the workspace path is not a directory`, `the runtime home is not usable` (one class for the *not-usable*, *unset*, **and** *standard-input-unreadable* paths), `the command-line usage is invalid`. | `Must-check`: `Presented Result`: read each stream as a terminal would (each `\n`-delimited line reduced to the text after its last carriage-return, with the erase-to-end-of-line applied); in that terminal read, exactly **one** stderr line begins with `tellme: `, and that line starts with `tellme: {reason}` — on a spinner-bearing failure the class phrase shares the erased spinner line, so the raw bytes may be `\r<erase>…\r<erase>tellme: {reason}`; any class-specific trailing detail (a path, a provider name, an OS error string) is **not part of the frozen contract**. `Should Not Happen`: the failure reason must not be swallowed or emitted only on stdout, and no second `tellme: `-prefixed line may exist. |
| `the run shows no turn chrome` | none | Not supported | `Channel`: standard output + standard error. `Source`: the turn chrome — the input-capture acknowledgement, the 80-column `─` rule, and the `╭─⠿ Turn …` header. | `Must-check`: `Presented Result`: neither the captured standard output nor standard error carries the input-capture acknowledgement, the 80-column `─` rule, or a `╭─⠿ Turn …` header line. `Should Not Happen`: the turn chrome must not appear on a `--version` run, on a prompt-less `--new`, or on any other non-prompt path. (Round 023: the `-i` interactive-prompt submit path is **no longer** a negative — the `-i` submit now shows the standard turn chrome.) |
| `the run reports no post-turn status` | none | Not supported | `Channel`: standard output + standard error. `Source`: the post-turn status — the metrics line and the `╰─⠿ Ready` summary. | `Must-check`: `Presented Result`: neither the captured standard output nor standard error carries a metrics line (`[HH:MM:SS] [<provider>] M: … H: … C: … Th: …`) or a `╰─⠿ Ready` summary line. `Should Not Happen`: the post-turn status must not appear when the provider reports no usage, nor on any non-prompt path (`--version`, `-l`, or a prompt-less `--new`). |
| `the run shows no progress spinner` | none | Not supported | `Channel`: standard output + standard error. `Source`: the turn spinner — a braille frame followed by a phase status. `Reading`: read each stream as a terminal would (each `\n`-delimited line reduced to the text after its last carriage-return, with the erase-to-end-of-line applied). | `Must-check`: `Presented Result`: neither the captured standard output nor standard error shows a spinner **residue** — read as a terminal, the surviving text carries no braille frame followed by a phase status such as `Thinking …` or `Executing …`. (A failed provider turn draws one frame and then synchronously clears it, so it leaves no residue.) `Should Not Happen`: the spinner must not appear when the diagnostic stream (`stderr`) is not a terminal, under `-r`, or on any non-prompt path (`--version`, `-l`, a prompt-less `--new`). (Round 023: the `-i` interactive-prompt submit path is **no longer** a negative — the `-i` submit now draws the spinner.) |
| `tellme exits with the configuration error code` | none | Not supported | `Code`: `3` (**pinned**, round 002 / FR-005) — a non-zero code distinct from success (0) and from every other error class (usage 2, environment 4, diagnostic 5). | `Must-check`: `Presented Result`: the exit code **equals the pinned configuration error code `3`**. `Should Not Happen`: it must not collapse to the success code or to any other error class. (Round 085: **promoted** from `configuration/dsl.md` — the step is shared by the `configuration` and `history` modules, so its single authoritative row lives at the root.) |

> **Round 085 (`085-dsl-topology-reconciliation`; closes [#173](https://github.com/gosharplite/tellme/issues/173)):** four **cross-module** rows were promoted from their module DSLs to this interface root — `the effective mode is "{mode}"` and `a configured provider "{provider}" whose endpoint answers with "{answer}"` (Given), `the operator starts tellme with the prompt "{prompt}"` (When), and `tellme exits with the configuration error code` (Then). Each is now used by two or more modules (`chat`/`configuration` + `history`), so the merged lookup (root ∪ own module) resolves it from every consumer — the `dsl-single-authority` rule (one authoritative row; never duplicated across levels). The row **semantics are unchanged**; only the authority level moved.

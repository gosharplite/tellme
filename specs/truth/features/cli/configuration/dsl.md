# configuration module DSL

Module-specific rows for the `configuration` module. Cross-module rows live in
[`../dsl.md`](../dsl.md). Merged with the interface root, every step in this module's feature must
match exactly one row.

## Given

| DSL Sentence | Gherkin Params | Data Table Params | Default Params | StepDef Implementation Semantics |
| --- | --- | --- | --- | --- |
| `no configuration exists at "{config_path}"` | `config_path`: string; path relative to the runtime home that must be absent. | Not supported | none | `How`: ensure nothing exists at `{home}/{config_path}`. `State landing`: the path is absent. `Write-back`: none. |
| `a malformed configuration "{config_path}"` | `config_path`: string; path relative to the runtime home. | Not supported | none | `How`: write a file at `{home}/{config_path}` containing invalid YAML. `State landing`: the file exists but cannot be parsed. `Write-back`: the malformed file. |
| `no configuration exists at the default location` | none | Not supported | `Default path`: `$TELL_ME_HOME/configs/<effective mode>.yaml`; the effective mode's file is absent. | `How`: ensure the default configuration path for the effective mode does not exist. `State landing`: no default configuration is discoverable. `Write-back`: none. |
| `a well-formed configuration "{config_path}" whose selected provider "{provider}" is in its registry` | `config_path`: string; path relative to the runtime home. `provider`: string; a provider key that must be present in the file registry. | Not supported | `PROVIDERS`: contains `{provider}`; `SELECTED_PROVIDER`: defaults to `{provider}`. | `How`: write a usable YAML whose `SELECTED_PROVIDER` is `{provider}` and whose `PROVIDERS` registry contains `{provider}`. `State landing`: the file's selected provider resolves to a registry entry. `Write-back`: the configuration file. |
| `a well-formed configuration "{config_path}" whose provider registry is empty` | `config_path`: string; path relative to the runtime home. | Not supported | none | `How`: write a usable YAML whose `PROVIDERS` registry is empty. `State landing`: the registry holds no entries. `Write-back`: the configuration file. |
| `a well-formed configuration "{config_path}" where provider "{provider}" specifies:` | `config_path`: string; path relative to the runtime home. `provider`: string; provider key. | Supported (headers `field`, `value`). | `SELECTED_PROVIDER`: defaults to `{provider}`. | `How`: write a YAML file at `{home}/{config_path}` whose `SELECTED_PROVIDER` is `{provider}` and whose `PROVIDERS.{provider}` defines the fields and values in the table. `State landing`: the configuration file exists with the specified provider fields. `Write-back`: the configuration file. |
| `the provider "{provider}" in configuration "{config_path}" includes custom headers:` | `provider`: string; provider key. `config_path`: string; path relative to runtime home. | Supported (headers `header`, `value`). | none | `How`: update `{home}/{config_path}` so `PROVIDERS.{provider}.HEADERS` contains the key-value pairs from the table. `State landing`: the provider's `HEADERS` map is populated. `Write-back`: the configuration file. |
| `a well-formed configuration "{config_path}" where provider "{provider}" specifies only mandatory fields:` | `config_path`: string; path relative to the runtime home. `provider`: string; provider key. | Supported (headers `field`, `value`). | `SELECTED_PROVIDER`: defaults to `{provider}`. Optional fields (`API_KEY`, `MAX_TOKENS`, `HEADERS`, `THINKING_BUDGET`, `THINKING_LEVEL`) are omitted. | `How`: write a YAML file at `{home}/{config_path}` whose `PROVIDERS.{provider}` contains only the mandatory fields from the table (`TYPE`, `MODEL`, `URL`). `State landing`: the provider entry omits all optional fields. `Write-back`: the configuration file. |
| `the environment variable "{var_name}" is set to "{var_value}"` | `var_name`: string; environment variable name. `var_value`: string; environment variable value. | Not supported | none | `How`: set `{var_name}={var_value}` in the subprocess environment. `State landing`: the environment variable is available during the run. `Write-back`: none. |
| `the environment variable "{var_name}" is unset` | `var_name`: string; environment variable name. | Not supported | none | `How`: ensure `{var_name}` is unset in the subprocess environment. `State landing`: the environment variable is absent. `Write-back`: none. |
| `a configuration "{config_path}" where selected provider "{provider}" is missing "{field}"` | `config_path`: string; path relative to runtime home. `provider`: string; provider key. `field`: string; mandatory field name. | Not supported | `SELECTED_PROVIDER`: `{provider}`. | `How`: write a YAML file at `{home}/{config_path}` whose `PROVIDERS.{provider}` omits the mandatory `{field}`. `State landing`: the selected provider is missing a required field. `Write-back`: the configuration file. |
| `a configuration "{config_path}" where selected provider "{provider}" has negative "{field}"` | `config_path`: string; path relative to runtime home. `provider`: string; provider key. `field`: string; numeric field name. | Not supported | `SELECTED_PROVIDER`: `{provider}`. | `How`: write a YAML file at `{home}/{config_path}` where `{field}` under `PROVIDERS.{provider}` is set to `-1`. `State landing`: the selected provider has a negative limit. `Write-back`: the configuration file. |
| `a well-formed configuration "{config_path}" where provider "{provider}" references unset variable "{var_name}"` | `config_path`: string; path relative to runtime home. `provider`: string; provider key. `var_name`: string; unset variable name. | Not supported | `SELECTED_PROVIDER`: `{provider}`. Ensure `{var_name}` is unset in environment. | `How`: write a YAML file at `{home}/{config_path}` where `PROVIDERS.{provider}.API_KEY` is `${{var_name}}` without default and `{var_name}` is unset. `State landing`: the selected provider contains an unresolved variable without default. `Write-back`: the configuration file. |
| `a well-formed configuration "{config_path}" whose rendered width is "{width}"` | `config_path`: string; path relative to the runtime home. `width`: string; the rendered width value written to the file. | Not supported | `SELECTED_PROVIDER`: defaults to a single well-formed provider entry. | `How`: write a resolvable YAML file at `{home}/{config_path}` whose top-level `WRAP_WIDTH` is `{width}`. `State landing`: the file carries the rendered width value. `Write-back`: the configuration file. |

## Then

| DSL Sentence | Gherkin Params | Data Table Params | Default Params | StepDef Implementation Semantics |
| --- | --- | --- | --- | --- |
| `tellme reports the configuration is ready` | none | Not supported | none | `Must-check`: `Presented Result`: stdout reports the configuration is ready. `Authoritative State`: the run validated the file and the effective selected provider. `Should Not Happen`: no configuration-error exit code. |

> **Round 085 (`085-dsl-topology-reconciliation`; closes [#173](https://github.com/gosharplite/tellme/issues/173)):** two rows were **promoted** to the interface root ([`../dsl.md`](../dsl.md)) — `the effective mode is "{mode}"` and `tellme exits with the configuration error code` — because each is now used by the `configuration` **and** the `history` modules. They resolve here through the merged lookup (root ∪ module); the row semantics are unchanged and there is no local duplicate (`dsl-single-authority`).

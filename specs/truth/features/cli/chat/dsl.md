# chat module DSL

Module-specific rows for the `chat` module — the single-prompt reasoning turn and its output presentation.
Cross-module rows live in [`../dsl.md`](../dsl.md). Merged with the interface root, every step in this
module's feature must match exactly one row.

> **Parameter escapes (round 005, grill Q6):** a quoted parameter on a single Gherkin line supports the
> escapes `\n`, `\t`, `\\`, and `\xHH` (hex byte); the step definitions decode them. This lets a
> newline-terminated or control-byte-bearing answer be written without a docstring, so the output
> contract is falsifiable.

> **Output rows (round 006):** under reference parity the **default** path renders the answer
> (`rendering-the-answer.feature` — the `is the rendered answer` row); the **`-r`** path is the byte-fidelity
> contract (`piping-the-answer-out.feature` — the `is exactly` row), and the `carries no terminal decoration`
> row is the FR-007 intent carrier for tellme's **own** chrome (the redirected stream adds no
> presentation control codes introduced by tellme; any control bytes the **answer itself** carries are
> passed through and are **not** flagged). The decoration row relies on the scenario's scripted answer
> (the `a configured provider … answers with …` Given) and fails loudly if it is absent.

> Round 004 (`004-first-reasoning-turn`): one `tellme "<prompt>"` performs **exactly one** non-streaming
> provider request and prints the answer. **(Round 078 reconciliation: a *retryable* provider failure
> now re-sends the same request up to twice — a turn may send 2–3 requests at the WIRE level — but it
> is still **one** AI-endpoint call for accounting (the round-078 note; ADR 0050); this round-004
> sentence is the single-request-per-round baseline, not a bound on transport re-sends.)** The provider transport is OpenAI-compatible; the request
> endpoint is the resolved provider `URL`. The E2E suite arranges all provider behaviour on an
> in-process **fake provider**, so "answers with", "error status", "unreachable", and "no usable
> answer" are all scripted on that fake (and a reachable fake doubles as the recording sink for the
> offline-path witness in the root DSL).

> **Ordering rows (round 010):** the ordering Thens (`… before the answer` / `… after the answer`) are asserted against the **merged** capture — the round-010 harness witness (`stdout` and `stderr` into one ordered buffer, the `2>&1` equivalent). They pin the *position* of the diagnostic lines relative to the answer bytes — the facet round 009 pinned only as presence. The answer itself stays on `stdout`.

> **Round 011 (`011-persona-and-payload-estimate`):** the persona rows arrange the configured `PERSON` (`the runtime home holds a configuration whose persona is …` / `… with no persona`) and assert the **leading `system` message** on the recorded request (`the request carried the persona …` / `the request carried no persona`). The estimate rows pin the **wire-faithful** pre-flight estimate (`the estimated payload exceeds the conversation messages alone` / `… is larger than the previous run's` / `… matches the previous run's` — persona + tool declarations + messages; responsive; deterministic). The existing `the request carried no earlier exchange` row is reworded so the conversation may be preceded by the leading persona `system` message (the default fixture script sets one).

> **Round 012 (`012-interactive-multiline-prompt`):** the interactive multi-line reader is a POSIX-terminal capability. The **positive** read — print the hint `[Reading multi-line input. Press Ctrl+C to cancel, or Ctrl+D to send]` to `stderr`, read the prompt from a terminal to EOF (`Ctrl+D`), bounded 1 MiB, one reasoning turn — is driven **end-to-end** through the `TELL_ME_FORCE_STDIN_TTY` diagnostic seam (`the operator is working at an interactive terminal`, review RF1) as well as at the unit layer (`internal/cli`); the empty/cancel contract (no request, exit `0`) stays a unit pin. Both a **piped** run and a run with the **null device** on standard input (`the operator starts tellme with the null device on standard input` — a character device that is NOT a terminal) print **no** reading announcement and take the boot/turn path (review B1/RF2). The `no reading announcement is reported` row asserts against the single-sourced product hint (`cli.MultiLineHint`), so a product-side text change cannot make the guard vacuous (review TD1). **POSIX-only, no Windows variant.** **Amendment A8:** a prompt-less `--new` on a terminal now archives the session **first**, then engages the reader (pinned by the `the operator starts a fresh session with "--new" and pipes "{content}"` row); a non-terminal prompt-less `--new` keeps its round-007 archive-and-exit behaviour (no announcement).

> **Round 013 (`013-vertex-gemini-provider`):** the CLI now also drives a **Vertex AI Gemini** provider (`TYPE: "gemini"`, an `aiplatform.googleapis.com` URL). A `gemini` provider's `API_KEY` ending in `.json` is a **service-account credential file**: tellme exchanges it (a JWT-RS256 assertion at the credential's `token_uri`) for an access token, sends `Authorization: Bearer`, and caches the token in memory for the run. A missing/unusable key fails with the frozen `the provider request failed` phrase (exit 6) and **no** silent bearer fallback; a family tellme cannot drive (e.g. `anthropic`) keeps its existing refusal. The `Gemini provider` Givens arrange a resolvable default config whose `TYPE` is `gemini` and whose `URL` is a **Vertex-shaped** endpoint pointing at the fake (`<fake>/v1/projects/<project>/locations/<location>/publishers/google/models`), with a service-account key file the fake's token endpoint backs; the fake serves the Vertex `:generateContent` shape and the token exchange. The frozen class-phrase vocabulary is **unchanged**.

> **Round 014 (`014-session-replay-fidelity`):** a resumed conversation that used a tool on a Vertex/Gemini provider replays the earlier tool step **with its persisted provider token** (`the request replayed the earlier tool step "{tool}" carrying the provider token "{token}"`), so the resume completes instead of failing at the provider; a conversation that used no tool, or used a tool on the OpenAI-compatible family, is unaffected (`the request replayed the earlier tool step "{tool}"`). The earlier tool-using turn is arranged by the `history` Given `the session history already holds a tool-using exchange carrying the provider token "{token}"`. The class-phrase vocabulary is **unchanged**.

> **Round 015 (`015-interactive-tui-prompt`):** the `-i` interactive TUI prompt offers live **suggestions** (recent prompts + workspace paths + registered tools), a **session dashboard**, and terminal keybindings; it is **opt-in** (`-i`/`USE_TUI_PROMPT` AND a terminal stdin), and a terminal invocation without it keeps the round-012 plain reader (coexist). Driven end-to-end through the `TELL_ME_FORCE_STDIN_TTY` seam with a **scripted key sequence**; the suggestion/dashboard Thens assert **presence** in the captured output (not exact ANSI bytes), and the shown/not-shown Thens assert a single-sourced announcement (`cli.TUIHint`). An `-i` submission is recorded in the **shared** prompt log in the identical `{"timestamp","prompt"}` shape; a one-shot or piped run reads and writes nothing (round 028 moved the log to the user-global `~/.tellme/global_prompts.jsonl`). The class-phrase vocabulary is **unchanged**.

> **Round 016 (`016-interactive-prompt-visual-parity`):** the `-i` prompt now matches `tell-me-go`'s surface — a **bordered** multi-line editor (`lipgloss.NormalBorder`) above a **styled** suggestion list, with the keybinding hints in the placeholder and **no** session metrics header (the round-015 dashboard header is **removed**, superseding its `reports the active provider` / `reports the session's token usage and turn count` rows). The suggestion refresh is **debounced** and **cancelable**, and entries spanning more than three lines are **dropped**; `Tab`/`Shift+Tab` **insert** the selection (replacing the last token for a single-token suggestion on a multi-word line). The chrome Thens assert **presence/absence** in the captured output (not exact ANSI bytes); the **resize/reflow** mechanics (a `WindowSizeMsg`-driven editor width), the **debounce timing** of the refresh, and the **last-token replacement** (a multi-word line + a single-token suggestion) are **unit** pins (no pty; see `features/acceptance/composing-with-settled-suggestions.feature` and `…/fitting-the-terminal-window.feature`). The class-phrase vocabulary is **unchanged**.

> **Round 019 (`019-turn-spinner`):** a prompt-bearing turn on the **non-TUI** surfaces shows a live **progress spinner** on `stderr` while it waits — brailled frames advancing on a ticker, a phase label naming the model (` Thinking [<model>]...`) or the tool(s) (` Executing [<tool>]...` / ` Executing tools [<a>, <b>]...`), and a `(<n>s)` elapsed counter (round 040 makes it the **dual** timer `({total}s {call}s)` — see the round-040 note below); while tools run the line also reports the machine's CPU/memory. The spinner is drawn **only when the diagnostic stream (`stderr`) is a terminal and `-r` is off** (`the diagnostics are shown at a terminal` — the interface-root row — arranges the round-019 `TELL_ME_FORCE_STDERR_TTY` seam, mirroring the round-012 stdin seam) — the spinner is a `stderr` diagnostic gated on `stderr` terminality like the reference; no standard-output probe is wired, so round-006 / PR #16 **Obs 1** stays **OPEN**. It yields the line to the answer and leaves no residue once the answer is written. The negatives are carried by the interface root (`the run shows no progress spinner`) on the `diagnostics` and `history` modules (**round 023**: no longer on the `-i` surface — the `-i` submit now draws the spinner); the frame **advancement** over ticks is a **unit** pin (no pty). The class-phrase vocabulary is **unchanged**.
>
> **Round 059 (`059-darwin-metrics-and-1hz-cadence`; ADR 0029):** the tool-phase resource segment's figures become **real on macOS** and **refresh once per second**. The round-019 macOS arm reported `0.0%` for every host — the CPU leg was a hardcoded stub (`return 0, …`) with no non-zero fallback, and the memory leg mis-decoded the NUL-trimmed `sysctl` value (`hw.memsize` → the first four bytes → `0`, so `total == 0` → `0.0%`; `vm.page_free_count` was 3 bytes → an outright error). The macOS sampler is now the reference's split: `darwin && cgo` reads machine-wide CPU from the Mach `host_statistics64` `HOST_CPU_LOAD_INFO` tick deltas and memory from `HOST_VM_INFO64` (`(active+wire+compressor)/hw.memsize`), while `darwin && !cgo` (the `CGO_ENABLED=0` cross-compile leg) reads the **process's own** CPU from `getrusage(RUSAGE_SELF)` (a real, non-zero measurement under load — never a hardcoded `0`; the first `runtime/metrics`-based attempt was rejected because `/cpu/classes/total:cpu-seconds` is the *available* CPU budget and read `0` on the darwin cgo-less host) normalised by `NumCPU`, and memory from the `sysctl` free+speculative+purgeable pages scaled by `0.6`; the `sysctl` reads go through `golang.org/x/sys/unix` (trim-safe), matching the reference. The spinner **throttles** the provider to at most one `Sample` per second (the reference's `metrics_shouldSample`; the last pair is reused between samples) while the braille frame keeps its 200 ms cadence — so the numbers no longer refresh 5×/s. The `the progress spinner reports the machine's resource usage` row's `必查` now also asserts a **non-zero** memory figure (the E2E witness for the decode fix); the **cadence** arithmetic (one sample per second, the clock injected) is a **unit** pin (`internal/ui`, `TestSpinnerResourceSampleThrottle`) — a deliberate narrowing, as a flat capture cannot observe a refresh rate. The linux sampler is unchanged. The class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 022 (`022-tool-loop-log-line`):** the `stderr` tool-loop log line is reshaped to a single timestamped line — `[HH:MM:SS] [Tool] <tool name> - <reason>` when the call states a reason, else `[HH:MM:SS] [Tool] <tool name>`. The round-008/021 `arguments=`/`result=` segments are **not** echoed (an **operator-chosen** shape; the reference instead decomposes tool activity into `[Tool Engine]`/`[Tool Reason]`/`[Tool Action]`/`[Tool Result]` lines). On a tool-using turn (≥1 tool log line), **one blank line** separates the tool-log block from the answer; the blank line is **ungated** (it follows the tool-log lines, so it appears on any tool-using surface, including the `-i` submit path). The separation is witnessed on two chrome surfaces (the positional Example and the `-i` submit Example). **Round 023** makes the `-i` submit a **chrome** surface, so the round-017 frame gap now supplies the single blank before the answer; the **negative** is re-anchored (PR #50 review B1) to `the pre-flight payload line is separated from the answer by a single blank line` on a **non-tool** `-i` run — exactly one blank (the frame gap, undoubled), so a stray round-022 blank would make it two. The **no-reason** row is exercised by a deliberately **schema-nonconforming** fixture — a `read_files` call scripted without `reason`, which the three filesystem tools' schema *requires* (round-021 D2) — covering the generic renderer for a tool that states no reason (PR #50 review TD2). The **in-order** row pins call order with an ordered assertion (PR #50 review TD3). The class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact. `[Tool Engine]` (round-056 clarification / review TD-056-2): the marker counts a tool round **that requests tools**, not one that executes at least one — a round whose calls are all refused still emits it, so "executed round" is qualified. A **refused** call still prints its `[Tool Action]` line and then `[Tool Result] <tool>: error: a reason is required…` (the gate runs after the action line) — a refused call is NOT an executed one, and the action+result pair alone does not imply execution.

> **Round 056 (`056-mcp-tool-call-reason`; ADR 0025; folds [#121](https://github.com/gosharplite/tellme/issues/121)):** *no reason, no go* is now **universal and enforced**. A tool call — tellme’s own **or** a remote MCP server’s — whose `reason` is missing or does not render is **refused**: the tool **does not execute** and the model receives a **recoverable** result asking it to retry with a reason (the round-032 TD1 nil-error convention; never the terminal request-level failure). The loop is the **single enforcement point** and **reuses** the round-046 single-owned `ReasonLine` predicate (no second reason-presence predicate); the MCP adapter adds **only** its `MCP_PAYLOAD` envelope check. An MCP tool is offered with tellme’s **own** declaration — a required `reason` + `MCP_PAYLOAD` carrying the server’s advertised schema **verbatim** (never mutated) — and `Execute` forwards **only** the `MCP_PAYLOAD` object (the outer keys never reach the server; an absent payload with a reason = `{}`; a shape violation is refused). **Consequences for earlier rows:** the round-022 **no-reason** fixture is superseded (a reason-less native call is now refused, not rendered generically), and the round-039 row `the action of the call without a reason begins after a blank line` is **RETIRED** (an executed call always states a reason, so a reason-less begin block is unreachable). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 034 (`034-tool-call-log-parity`) — supersedes the round-022 shape above:** the `stderr` tool-loop log is now the reference's **decomposed** rendering — `[Tool Engine] Step i/M` (once per **executed** round; the bound-reached call renders a frame but no engine line), `[Tool Reason]`, `[Tool Action] <tool>(<sorted args>)` (`reason` excluded; values rune-capped at **500** with one U+2026 inside the cap — raised from 189 by round 057, ADR 0027), `[Tool Output]` (shell-class, live, **bounded-and-stopped**), and `[Tool Result] <tool>: <snippet>` (rune-capped at **200**); the round's reasons are re-emitted **grouped** at each call's post-call tail, and rounds are framed **per AI-endpoint call** with the final call's tail deferred past the answer. The round-022 single-line `[Tool] <tool name> - <reason>` shape, its no-reason form, and its one-blank-line-before-the-answer rule are **retired** (the round-022 rows were removed; the reason row was retargeted, not removed).

> **Round 023 (`023-interactive-prompt-teardown`):** on submit (`Ctrl+S`/`Alt+Enter`) or abort (`Esc`/`Ctrl+C`) the `-i` interactive prompt **clears** its editor frame (reference parity — the box does not linger); a submitted prompt then **continues on the standard turn surface** — the submitted (trimmed) prompt is **echoed** on `stderr` before the input-capture acknowledgement, then the standard chrome (`─` rule + `╭─⠿ Turn N - <mode>` header) and (at a terminal `stderr`, not `-r`) the live spinner. The `-i` surface is therefore **no longer a chrome/spinner negative** (the interface-root `the run shows no turn chrome` / `the run shows no progress spinner` rows drop their `-i` clause, and `presenting-the-turn`'s `the run shows no turn chrome` Rule is removed). The editor-**clear** is a **unit** pin (`internal/ui/tui/prompt`); the handoff (echo + chrome + spinner) is witnessed E2E. The other prompt surfaces are unchanged and do **not** echo. The class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 024 (`024-tool-resource-contract-and-execute-command`):** the agent tool surface gains a **bash-first command tool** (`execute_command`) and a cross-cutting **tool resource contract**. `execute_command` runs the model's `command` through `bash -c` (no `pipe_commands`, no security/consent); a **non-zero exit is a successful result** carrying the exit status (not a failure); a command that exceeds its effective `timeout` is **stopped as a process group**; and an optional `output_file`/`append` binds the child's output **directly to a file** (streamed to disk; no inline preview; the result reports the target). Every agent tool (`list_files`, `read_files`, `get_tree`, `execute_command`) now accepts optional **`max_output_tokens`** and **`timeout`** params — resolved **default → param → ceiling** and enforced by the loop, with **every** tool bounding its own output at the source. The bound derives from the **effective budget** = `min(configured MAX_HISTORY_TOKENS, the model's configured context window)`: default `max_output_tokens` = `effectiveBudget ÷ 4`, ceiling = `effectiveBudget ÷ 2` (a headroom reservation); shell `timeout` default 300 s, readers 30 s, ceiling 7200 s. The readers therefore read files **whole** (the fixed 100000-byte / 1 MiB caps are retired) up to the aggregate bound, and a request that cannot return every file reports the ones it did not (a **skip** marker). The child's streams are never inherited from tellme's stdout/stderr — they are read through **bounded pipes** (`StdoutPipe`/`StderrPipe`, never a `cmd.Stdout` buffer, which `os/exec` reads to EOF). Marker wording is fixed at the step-definition layer. **Grill fold (PR #54):** the bound is realised as a single **byte** budget via the contract-owned `bytesPerToken = 4` conversion (`effectiveBudget ÷ 4` tokens → `effectiveBudget` bytes; default **`1000000 B`**), and the loop clamps on **raw byte length** (never the estimator — no `+4` double-trim). Three **distinct** cut outcomes: **trimmed** (the byte budget), **stopped** (the *time* budget — a **nil-error** timeout result, never the loop's `error: ` path; FR-018, uniform across every tool), and **skip** (a `read_files` file not returned). Round-024 witnesses beyond the shell: a `list_files`/`get_tree` **bound** witness (a scripted small `max_output_tokens` trips the truncation marker — FR-011), and a **process-tree stop** witness (a command that spawns a long-lived descendant is stopped *with* its descendants). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 025 (`025-spinner-width-safety`):** the round-019 spinner's tool-phase label is **bounded** — for several tools it reads ` Executing tools [<first> and <N-1> more]...` (the first tool name + the count of the rest; the single-tool ` Executing [<name>]...` and no-names ` Executing tools...` forms are **unchanged**), so the line can no longer overrun the terminal and clip the ` [CPU: … | MEM: …]` segment (issue #55). The presenter also makes the clear **width-safe**: it tracks the rendered-row count of its last frame and erases **every** occupied row, so an over-wide (soft-wrapped) frame leaves no residue (the `the progress spinner no longer appears once the answer is written` row still holds). The terminal width comes from an injected `columns` seam (default: `golang.org/x/term.GetSize` on the `stderr` fd — already a direct dependency; the diagnostic `TELL_ME_FORCE_STDERR_COLS` seam drives it in E2E/unit, alongside `TELL_ME_FORCE_STDERR_TTY`); an unknown width degrades to a single-row best effort. The bounded label is witnessed E2E; the row-aware clear is a **unit** pin (a flat capture cannot reproduce a terminal grid) plus the clear-byte-sequence witness. The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 035 (`035-spinner-tail-residue`):** the round-034 per-call **tail** (the grouped `[Tool Reason]` lines + measured payload line + metrics line + `Ready`) is written with the progress indicator **yielded** — a **phase-boundary** yield: the presenter synchronously **clears** the spinner **before** the tail's first line and does **not** resume it (the next waiting phase — the next call's `OnInferenceStart`, or the turn's `Stop()` — re-activates it). So the tail's lines begin on their own rows and **no braille-frame residue survives into the finished turn** (issue #72: the tail previously shared a physical row with the live frame, and the frame text baked into that row was never erased). The tool-log lines and the `[Tool Output]` block keep their existing clear+write+resume yields; the deferred final tail (emitted after `Stop()`) is unchanged. This makes the **whole-stream** residue row `the run shows no progress spinner` hold for the **gated tool-tail** path — previously only the post-answer row (`the progress spinner no longer appears once the answer is written`) was exercised on a terminal tool round, so the pre-answer tail collision was not covered. The fix is witnessed E2E by a new `presenting-the-progress-spinner` Example (the gate + a scripted tool round + the whole-stream residue row) and, for the emit/yield ordering, by a **unit** pin (a flat capture has no terminal grid). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.
>
> **Round 036 (`036-tool-reason-sanitize`):** the model-authored `[Tool Reason]` value is **sanitized and capped like its siblings**. `FormatToolReason` folds embedded `\n`/`\r` to spaces, trims the surrounding whitespace, and **caps the folded reason at 200 rendered runes** (one U+2026 counted inside the cap, cut on a rune boundary) — identical mechanics to `FormatToolResult` (`resultValueCap = 200`) and `FormatToolAction` (`argValueCap = 189`, since round 057 `= 500`). So a multi-line or over-long model reason can no longer break its own one-line row (a `\n` previously **split** the row; a `\r` **truncated** it, dropping the prefix). A **blank** reason (empty or whitespace-only after folding+trimming) emits **no** `[Tool Reason]` line on either surface (the loop action line or the per-call tail) — the round-022 **B1** intent ("a whitespace-only reason takes the no-tail branch"), with the guard moved to the emission sites — `agentloop.logAction` and `agentloop.reasonsOf` (the loop-tier filters; `reasonsOf` feeds the grouped tail) plus a defensive guard in the `callRenderer.OnCallEnd` `emit` closure — so the pure formatter is not asked to emit an empty-string sentinel. **This restores round-022 B1's fold guarantee, which round 034 dropped without recording it** — the cap set grows from `{189, 200}` to `{189, 200, 200}`, and the drop + this decision are recorded in the new **ADR 0006** (`docs/decisions/0006-tool-reason-fold-and-cap.md`). **Witness: a hostile-fixture unit pin** (a `\n` reason, a `\r` reason, a whitespace-only reason, and a 201-rune over-cap reason), because the E2E surface is structurally blind to this class (the residue rows look for a braille frame + phase status, which neither `\n` nor `\r` produces). **No new `DSLRow` and no new Example** are added (a deliberate permanent narrowing — the unit pin is the carrier). The sibling formatters, the class-phrase vocabulary, and `stdout` are **unchanged**. This is independent of the round-035 spinner-yield fix: sanitizing the reason keeps a *row* intact; round 035 keeps *the row the spinner shares* clear. **Round 046 (R4 of [#92](https://github.com/gosharplite/tellme/issues/92)):** the blank-reason predicate is consolidated to **one owner** — `ui.ToolLineRenderer.ReasonLine`, which returns the rendered line **and** the `renders` decision from a **single** evaluation of the reason transform (`ui.toolReasonText`). The loop's `logAction` (the begin-line guard) and `reasonsOf` (the tail filter) consume that owner; the third — the **defensive** check that lived in the `callRenderer.OnCallEnd` `emit` closure — is **DELETED** (it could never fire, because `reasonsOf` had already filtered). So of the three sites named above, the two loop-tier ones still stand and **the third no longer exists**; the pure formatter is still never asked to emit an empty-string sentinel. Policy: **ADR 0015** (`docs/decisions/0015-loop-presentation-port.md`).

> **Round 057 (`057-tool-chrome-colour-and-payload-delta`) — ADR 0027:** two `[Tool …]` chrome elements gain a terminal-gated accent and two numbers move: (i) the whole `[Tool Output]` **header** line and **both** horizontal separators are wrapped in the reference's grey `\033[0;90m` (the streamed **content** lines stay plain — the round-038 sanitizer governs them); (ii) the whole `[Tool Action]` line is wrapped in the reference's yellow `\033[0;33m`; (iii) `argValueCap` rises **189 → 500** (same rune-safe mechanic, one U+2026 inside the cap — the recorded reference divergence now differs in magnitude too, since the reference caps at 189 **bytes**); (iv) the **estimated** pre-flight payload line becomes `Payload: +<delta> ~<tokens> tokens - <mode> - <model>` — the signed increment over the previous estimate **in the same run** (in-memory, session-scoped; `+0` with no predecessor, a negative value when the payload shrank) — and **drops** the `/budget`; the **measured** line is unchanged (`<tokens>/<budget>`). The colour obeys the round-054 gate (terminal `stderr` + `-r` off) and never enters `stdout` or `turns.log` (a file leg renders plain by construction).

> **Round 027 (`027-ai-call-turn-counter`):** the turn header's `<N>` now counts the session's **AI-endpoint calls** (provider inference rounds) rather than completed user turns — the running index of this prompt's first call (`Σ` of the active session's `history_entry` `calls` + 1), matching `tell-me-go`'s counter at that prompt's first call. The chrome **cadence and format are unchanged** (still one header + one `╰─⠿ Ready` per prompt; the reference instead emits a pair **per provider call**): a **tool-less** turn advances the number by one, a **tool-using** turn by its inference-round count, and an internal retry (backoff / empty-response) does **not** count. The two arranged tool-using history Givens now write `calls: 2` (a tool-using turn makes two requests); a legacy or arranged plain line without `calls` counts as 1. It also fixes `--new` on the `-i` surface (round-027 fold): `--new` now archives before the interactive read for **both** terminal readers, so `tellme --new -i` starts at `Turn 1` (a new When row runs `tellme --new -i`). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 028 (`028-user-global-prompt-log`):** the shared prompt log moves to a **user-global** file at `~/.tellme/global_prompts.jsonl` (resolved via `os.UserHomeDir()`) — read + written only there, shared across every environment/repository/mode (the second artifact in the `~/.tellme/` root, with the round-026 tool-usage log). When the file is absent the adapter **seeds** it with a verbatim copy of the environment-scoped `$TELL_ME_HOME/output/global_prompts.jsonl` (copy, not move; never overwrites an existing destination; a missing source starts empty), so the operator's earlier prompts are carried over. **Recorded divergence:** tellme no longer shares the log with `tell-me-go` (which keeps `$TELL_ME_HOME/output/global_prompts.jsonl`) and skips its legacy locations. The class-phrase vocabulary is **unchanged**.

> **Round 029 (`029-agent-write-tools`):** the agent tool surface gains its first **write pair**. `write_file` creates a file with exactly the given `content`, creating missing parent folders, and **refuses to overwrite an existing file** (create-only; the write is atomic via a temp file + `rename` in the target folder, so the destination is never a partial file). `replace_text` replaces a block only when it is **uniquely** present and fails (leaving the file untouched) on **0** or **>1** matches; an empty `old_text`, a missing file, or a create over an existing file is a recoverable **tool error** fed back to the model (never the terminal `the tool request failed`). > **Round 032 (`032-mcp-client`):** tellme gains a **remote (Streamable HTTP) MCP client**. > **Round 030 (`030-provider-truncation-guard`):** the provider transports read the **finish reason** and turn an **output-cap truncation** into a loud provider failure instead of returning a (possibly corrupted) reply.

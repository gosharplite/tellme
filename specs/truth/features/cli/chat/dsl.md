# chat module DSL

Module-specific rows for the `chat` module — the single-prompt reasoning turn and its output presentation.
Cross-module rows live in [`../dsl.md`](../dsl.md). Merged with the interface root, every step in this
module's feature must match exactly one row.

> **Parameter escapes (round 005, grill Q6):** a quoted parameter on a single Gherkin line supports the
> escapes `\n`, `\t`, `\\`, and `\xHH` (hex byte); the step definitions decode them. This lets a
> newline-terminated or control-byte-bearing answer be written without a docstring, so the output
> contract is falsifiable.

> **Output rows (round 006):** under reference parity the **default** path renders the answer
> (`rendering-the-answer.feature` — the `is the rendered answer` row); the **`-r`** path is the byte-fidelity
> contract (`piping-the-answer-out.feature` — the `is exactly` row), and the `carries no terminal decoration`
> row is the FR-007 intent carrier for tellme's **own** chrome (the redirected stream adds no
> presentation control codes introduced by tellme; any control bytes the **answer itself** carries are
> passed through and are **not** flagged). The decoration row relies on the scenario's scripted answer
> (the `a configured provider … answers with …` Given) and fails loudly if it is absent.

> Round 004 (`004-first-reasoning-turn`): one `tellme "<prompt>"` performs **exactly one** non-streaming
> provider request and prints the answer. The provider transport is OpenAI-compatible; the request
> endpoint is the resolved provider `URL`. The E2E suite arranges all provider behaviour on an
> in-process **fake provider**, so "answers with", "error status", "unreachable", and "no usable
> answer" are all scripted on that fake (and a reachable fake doubles as the recording sink for the
> offline-path witness in the root DSL).

> **Ordering rows (round 010):** the ordering Thens (`… before the answer` / `… after the answer`) are asserted against the **merged** capture — the round-010 harness witness (`stdout` and `stderr` into one ordered buffer, the `2>&1` equivalent). They pin the *position* of the diagnostic lines relative to the answer bytes — the facet round 009 pinned only as presence. The answer itself stays on `stdout`.

> **Round 011 (`011-persona-and-payload-estimate`):** the persona rows arrange the configured `PERSON` (`the runtime home holds a configuration whose persona is …` / `… with no persona`) and assert the **leading `system` message** on the recorded request (`the request carried the persona …` / `the request carried no persona`). The estimate rows pin the **wire-faithful** pre-flight estimate (`the estimated payload exceeds the conversation messages alone` / `… is larger than the previous run's` / `… matches the previous run's` — persona + tool declarations + messages; responsive; deterministic). The existing `the request carried no earlier exchange` row is reworded so the conversation may be preceded by the leading persona `system` message (the default fixture script sets one).

> **Round 012 (`012-interactive-multiline-prompt`):** the interactive multi-line reader is a POSIX-terminal capability. The **positive** read — print the hint `[Reading multi-line input. Press Ctrl+C to cancel, or Ctrl+D to send]` to `stderr`, read the prompt from a terminal to EOF (`Ctrl+D`), bounded 1 MiB, one reasoning turn — is driven **end-to-end** through the `TELL_ME_FORCE_STDIN_TTY` diagnostic seam (`the operator is working at an interactive terminal`, review RF1) as well as at the unit layer (`internal/cli`); the empty/cancel contract (no request, exit `0`) stays a unit pin. Both a **piped** run and a run with the **null device** on standard input (`the operator starts tellme with the null device on standard input` — a character device that is NOT a terminal) print **no** reading announcement and take the boot/turn path (review B1/RF2). The `no reading announcement is reported` row asserts against the single-sourced product hint (`cli.MultiLineHint`), so a product-side text change cannot make the guard vacuous (review TD1). **POSIX-only, no Windows variant.** **Amendment A8:** a prompt-less `--new` on a terminal now archives the session **first**, then engages the reader (pinned by the `the operator starts a fresh session with "--new" and pipes "{content}"` row); a non-terminal prompt-less `--new` keeps its round-007 archive-and-exit behaviour (no announcement).

> **Round 013 (`013-vertex-gemini-provider`):** the CLI now also drives a **Vertex AI Gemini** provider (`TYPE: "gemini"`, an `aiplatform.googleapis.com` URL). A `gemini` provider's `API_KEY` ending in `.json` is a **service-account credential file**: tellme exchanges it (a JWT-RS256 assertion at the credential's `token_uri`) for an access token, sends `Authorization: Bearer`, and caches the token in memory for the run. A missing/unusable key fails with the frozen `the provider request failed` phrase (exit 6) and **no** silent bearer fallback; a family tellme cannot drive (e.g. `anthropic`) keeps its existing refusal. The `Gemini provider` Givens arrange a resolvable default config whose `TYPE` is `gemini` and whose `URL` is a **Vertex-shaped** endpoint pointing at the fake (`<fake>/v1/projects/<project>/locations/<location>/publishers/google/models`), with a service-account key file the fake's token endpoint backs; the fake serves the Vertex `:generateContent` shape and the token exchange. The frozen class-phrase vocabulary is **unchanged**.

> **Round 014 (`014-session-replay-fidelity`):** a resumed conversation that used a tool on a Vertex/Gemini provider replays the earlier tool step **with its persisted provider token** (`the request replayed the earlier tool step "{tool}" carrying the provider token "{token}"`), so the resume completes instead of failing at the provider; a conversation that used no tool, or used a tool on the OpenAI-compatible family, is unaffected (`the request replayed the earlier tool step "{tool}"`). The earlier tool-using turn is arranged by the `history` Given `the session history already holds a tool-using exchange carrying the provider token "{token}"`. The class-phrase vocabulary is **unchanged**.

> **Round 015 (`015-interactive-tui-prompt`):** the `-i` interactive TUI prompt offers live **suggestions** (recent prompts + workspace paths + registered tools), a **session dashboard**, and terminal keybindings; it is **opt-in** (`-i`/`USE_TUI_PROMPT` AND a terminal stdin), and a terminal invocation without it keeps the round-012 plain reader (coexist). Driven end-to-end through the `TELL_ME_FORCE_STDIN_TTY` seam with a **scripted key sequence**; the suggestion/dashboard Thens assert **presence** in the captured output (not exact ANSI bytes), and the shown/not-shown Thens assert a single-sourced announcement (`cli.TUIHint`). An `-i` submission is recorded in the **shared** prompt log (`$TELL_ME_HOME/output/global_prompts.jsonl`, the `output/` root) in the identical `{"timestamp","prompt"}` shape; a one-shot or piped run writes nothing. The class-phrase vocabulary is **unchanged**.

> **Round 016 (`016-interactive-prompt-visual-parity`):** the `-i` prompt now matches `tell-me-go`'s surface — a **bordered** multi-line editor (`lipgloss.NormalBorder`) above a **styled** suggestion list, with the keybinding hints in the placeholder and **no** session metrics header (the round-015 dashboard header is **removed**, superseding its `reports the active provider` / `reports the session's token usage and turn count` rows). The suggestion refresh is **debounced** and **cancelable**, and entries spanning more than three lines are **dropped**; `Tab`/`Shift+Tab` **insert** the selection (replacing the last token for a single-token suggestion on a multi-word line). The chrome Thens assert **presence/absence** in the captured output (not exact ANSI bytes); the **resize/reflow** mechanics (a `WindowSizeMsg`-driven editor width), the **debounce timing** of the refresh, and the **last-token replacement** (a multi-word line + a single-token suggestion) are **unit** pins (no pty; see `features/acceptance/composing-with-settled-suggestions.feature` and `…/fitting-the-terminal-window.feature`). The class-phrase vocabulary is **unchanged**.

> **Round 019 (`019-turn-spinner`):** a prompt-bearing turn on the **non-TUI** surfaces shows a live **progress spinner** on `stderr` while it waits — brailled frames advancing on a ticker, a phase label naming the model (` Thinking [<model>]...`) or the tool(s) (` Executing [<tool>]...` / ` Executing tools [<a>, <b>]...`), and a `(<n>s)` elapsed counter; while tools run the line also reports the machine's CPU/memory. The spinner is drawn **only when the diagnostic stream (`stderr`) is a terminal and `-r` is off** (`the diagnostics are shown at a terminal` — the interface-root row — arranges the round-019 `TELL_ME_FORCE_STDERR_TTY` seam, mirroring the round-012 stdin seam) — the spinner is a `stderr` diagnostic gated on `stderr` terminality like the reference; no standard-output probe is wired, so round-006 / PR #16 **Obs 1** stays **OPEN**. It yields the line to the answer and leaves no residue once the answer is written. The negatives are carried by the interface root (`the run shows no progress spinner`) on the `diagnostics` and `history` modules (**round 023**: no longer on the `-i` surface — the `-i` submit now draws the spinner); the frame **advancement** over ticks is a **unit** pin (no pty). The class-phrase vocabulary is **unchanged**.

> **Round 022 (`022-tool-loop-log-line`):** the `stderr` tool-loop log line is reshaped to a single timestamped line — `[HH:MM:SS] [Tool] <tool name> - <reason>` when the call states a reason, else `[HH:MM:SS] [Tool] <tool name>`. The round-008/021 `arguments=`/`result=` segments are **not** echoed (an **operator-chosen** shape; the reference instead decomposes tool activity into `[Tool Engine]`/`[Tool Reason]`/`[Tool Action]`/`[Tool Result]` lines). On a tool-using turn (≥1 tool log line), **one blank line** separates the tool-log block from the answer; the blank line is **ungated** (it follows the tool-log lines, so it appears on any tool-using surface, including the `-i` submit path). The separation is witnessed on two chrome surfaces (the positional Example and the `-i` submit Example). **Round 023** makes the `-i` submit a **chrome** surface, so the round-017 frame gap now supplies the single blank before the answer; the **negative** is re-anchored (PR #50 review B1) to `the pre-flight payload line is separated from the answer by a single blank line` on a **non-tool** `-i` run — exactly one blank (the frame gap, undoubled), so a stray round-022 blank would make it two. The **no-reason** row is exercised by a deliberately **schema-nonconforming** fixture — a `read_files` call scripted without `reason`, which the three filesystem tools' schema *requires* (round-021 D2) — covering the generic renderer for a tool that states no reason (PR #50 review TD2). The **in-order** row pins call order with an ordered assertion (PR #50 review TD3). The class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 023 (`023-interactive-prompt-teardown`):** on submit (`Ctrl+S`/`Alt+Enter`) or abort (`Esc`/`Ctrl+C`) the `-i` interactive prompt **clears** its editor frame (reference parity — the box does not linger); a submitted prompt then **continues on the standard turn surface** — the submitted (trimmed) prompt is **echoed** on `stderr` before the input-capture acknowledgement, then the standard chrome (`─` rule + `╭─⠿ Turn N - <mode>` header) and (at a terminal `stderr`, not `-r`) the live spinner. The `-i` surface is therefore **no longer a chrome/spinner negative** (the interface-root `the run shows no turn chrome` / `the run shows no progress spinner` rows drop their `-i` clause, and `presenting-the-turn`'s `the run shows no turn chrome` Rule is removed). The editor-**clear** is a **unit** pin (`internal/ui/tui/prompt`); the handoff (echo + chrome + spinner) is witnessed E2E. The other prompt surfaces are unchanged and do **not** echo. The class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 024 (`024-tool-resource-contract-and-execute-command`):** the agent tool surface gains a **bash-first command tool** (`execute_command`) and a cross-cutting **tool resource contract**. `execute_command` runs the model's `command` through `bash -c` (no `pipe_commands`, no security/consent); a **non-zero exit is a successful result** carrying the exit status (not a failure); a command that exceeds its effective `timeout` is **stopped as a process group**; and an optional `output_file`/`append` binds the child's output **directly to a file** (streamed to disk; no inline preview; the result reports the target). Every agent tool (`list_files`, `read_files`, `get_tree`, `execute_command`) now accepts optional **`max_output_tokens`** and **`timeout`** params — resolved **default → param → ceiling** and enforced by the loop, with **every** tool bounding its own output at the source. The bound derives from the **effective budget** = `min(configured MAX_HISTORY_TOKENS, the model's configured context window)`: default `max_output_tokens` = `effectiveBudget ÷ 4`, ceiling = `effectiveBudget ÷ 2` (a headroom reservation); shell `timeout` default 300 s, readers 30 s, ceiling 7200 s. The readers therefore read files **whole** (the fixed 100000-byte / 1 MiB caps are retired) up to the aggregate bound, and a request that cannot return every file reports the ones it did not (a **skip** marker). The child's streams are never inherited from tellme's stdout/stderr — they are read through **bounded pipes** (`StdoutPipe`/`StderrPipe`, never a `cmd.Stdout` buffer, which `os/exec` reads to EOF). Marker wording is fixed at the step-definition layer. **Grill fold (PR #54):** the bound is realised as a single **byte** budget via the contract-owned `bytesPerToken = 4` conversion (`effectiveBudget ÷ 4` tokens → `effectiveBudget` bytes; default **`1000000 B`**), and the loop clamps on **raw byte length** (never the estimator — no `+4` double-trim). Three **distinct** cut outcomes: **trimmed** (the byte budget), **stopped** (the *time* budget — a **nil-error** timeout result, never the loop's `error: ` path; FR-018, uniform across every tool), and **skip** (a `read_files` file not returned). Round-024 witnesses beyond the shell: a `list_files`/`get_tree` **bound** witness (a scripted small `max_output_tokens` trips the truncation marker — FR-011), and a **process-tree stop** witness (a command that spawns a long-lived descendant is stopped *with* its descendants). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 025 (`025-spinner-width-safety`):** the round-019 spinner's tool-phase label is **bounded** — for several tools it reads ` Executing tools [<first> and <N-1> more]...` (the first tool name + the count of the rest; the single-tool ` Executing [<name>]...` and no-names ` Executing tools...` forms are **unchanged**), so the line can no longer overrun the terminal and clip the ` [CPU: … | MEM: …]` segment (issue #55). The presenter also makes the clear **width-safe**: it tracks the rendered-row count of its last frame and erases **every** occupied row, so an over-wide (soft-wrapped) frame leaves no residue (the `the progress spinner no longer appears once the answer is written` row still holds). The terminal width comes from an injected `columns` seam (default: `golang.org/x/term.GetSize` on the `stderr` fd — already a direct dependency; the diagnostic `TELL_ME_FORCE_STDERR_COLS` seam drives it in E2E/unit, alongside `TELL_ME_FORCE_STDERR_TTY`); an unknown width degrades to a single-row best effort. The bounded label is witnessed E2E; the row-aware clear is a **unit** pin (a flat capture cannot reproduce a terminal grid) plus the clear-byte-sequence witness. The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 027 (`027-ai-call-turn-counter`):** the turn header's `<N>` now counts the session's **AI-endpoint calls** (provider inference rounds) rather than completed user turns — the running index of this prompt's first call (`Σ` of the active session's `history_entry` `calls` + 1), matching `tell-me-go`'s counter at that prompt's first call. The chrome **cadence and format are unchanged** (still one header + one `╰─⠿ Ready` per prompt; the reference instead emits a pair **per provider call**): a **tool-less** turn advances the number by one, a **tool-using** turn by its inference-round count, and an internal retry (backoff / empty-response) does **not** count. The two arranged tool-using history Givens now write `calls: 2` (a tool-using turn makes two requests); a legacy or arranged plain line without `calls` counts as 1. It also fixes `--new` on the `-i` surface (round-027 fold): `--new` now archives before the interactive read for **both** terminal readers, so `tellme --new -i` starts at `Turn 1` (a new When row runs `tellme --new -i`). The frozen class-phrase vocabulary is **unchanged**; `stdout` stays byte-exact.

> **Round 026 (`026-tool-usage-accounting`):** every **executed** agent-tool invocation is recorded to a **user-global, append-only** JSON-Lines log at `~/.tellme/tools-count.jsonl` (the CHILD's `HOME`, resolved via `os.UserHomeDir()`; the E2E harness points `HOME` at a per-scenario temp dir, so the log inspected here is the scenario's own), one record per invocation `{"timestamp":"<RFC3339>","tool":"<wire name>","outcome":"<ok|error|timeout>"}` — `ok` = a result (incl. a bounded/truncated one), `error` = a non-nil tool error, `timeout` = a nil-error result at the per-call deadline (the round-024 FR-018 "stopped" path). The write is **best-effort** (a log failure or an unresolvable home is a silent no-op) and emits nothing on `stdout`/`stderr`. The log is **global** (shared across repos/envs/personas) and **never reset by `--new`** (a fresh session must not zero the counters). The operator reviews the roll-up **offline** — the `--tool-usage` flag prints, per registered tool in registry order, the invocations and the `ok`/`error`/`timeout` breakdown to `stdout` and exits (no provider, no stdin), mirroring `-l`/`-d`. `stdout` on the prompt path stays byte-exact; the frozen class-phrase vocabulary is **unchanged**. The classification reads **only** the loop-owned `err` + the per-call `ctx` deadline — under the stated **loop↔tool invariant** that a tool produces a timeout result only when that deadline expired (no result-text sniffing); on a rare trim-vs-deadline collision the record follows the deadline signal (`timeout`) while the result text stays a bounded success. The report **streams** the log (O(tools) memory) and is **resilient** to malformed/torn lines (skip best-effort).

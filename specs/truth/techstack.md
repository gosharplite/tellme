The prompt shows **no** dashboard header, **no** status/keybinding line, and **no** `?` help overlay (the hints live in the placeholder). Keybindings unchanged (`Tab`/`Shift+Tab`, `Ctrl+S`/`Alt+Enter`, `Esc`/`Ctrl+C`). Read **newest-first + deduped** to seed suggestions; written **only under `-i`** (append-only `O_APPEND|O_CREATE`, detached/bounded so it never blocks the prompt); best-effort compaction at ≈150 KiB keeping ≤1200 unique entries. No new accounting. |
| Output rendering | `github.com/charmbracelet/glamour` (v1.0.0) | Render the provider's answer as formatted Markdown→ANSI on the default path (reference parity, round 006); built with `WithStandardStyle` (+ `GLAMOUR_STYLE` env) and `WithEmoji`; the LaTeX→Unicode sanitizer runs before rendering; on init failure it degrades to raw text with a single warning (reference ADR-007 parity). The project's first presentation dependency; pulls `lipgloss`/`termenv`/`reflow` transitively |
| Raw output flag | `spf13/pflag` boolean `-r`/`--raw` | Bypass rendering and print the answer verbatim as plain text (the reference's pipeline contract, round 006). Rendering is gated by `-r` **alone** — never by whether stdout is a terminal |
| Session history store | Go stdlib (`encoding/json` over `os`) | Persist each **completed** turn as one line of an **append-only JSON-Lines** file, `history.jsonl`, under the per-mode session workspace (`$TELL_ME_HOME/output/<mode>/`); written only after the turn completes; the provider's answer text is stored verbatim (content, not the rendered form). Read on resume; no database, no wrapper (round 007). Round 008 **widens** the line to embed the turn's tool steps (`{prompt, answer, steps:[…]}`) — still append-after-complete, fixed field order, no timestamp/id — and replays them into the conversation on resume; `-l` still reads only `prompt`/`answer`; no per-step id is stored — the adapter synthesises a deterministic `tool_call_id` (`call_step_<step>`) on replay (TD-2). Round 014 adds a nullable, provider-agnostic **`signature`** to each step (`{tool, arguments, result, signature?}`) — omitted when empty so existing lines stay byte-identical — and replays it on resume, so a tool-using Gemini session resumes faithfully (Vertex requires the `thoughtSignature` echoed on a replayed `functionCall`) |
| Session usage log | Go stdlib (`encoding/json` over `os`) | Round 018: one JSON record per **API call** — `{timestamp, provider, model, cached_tokens, prompt_tokens, response_tokens, total_tokens, thinking_tokens, cost}` — appended to `output/<mode>/tokens.log` after each call; the `╰─⠿ Ready` summary sums the file (session token totals + session cost); `--new` archives/rotates it alongside `history.jsonl` |
| Session lifecycle flags | `spf13/pflag` `--new` (bool) + `-l N` (int) | `--new` starts a fresh session, **archiving** the active history into `history.archive.jsonl` (append; retained, not destroyed); `-l N` prints the last N persisted messages as plain text and exits **without** a provider request. N must be a positive integer (round 007). `-l` lists **prompt/answer only** — the widened tool activity (round 008) is not surfaced |
| Read-only filesystem tools | Go stdlib (`os`, `path/filepath`, `io`, `sort`, `strings`) | Three read-only, local agent tools with **wire-valid snake_case** names (the OpenAI `tools[i].function.name` schema `^[a-zA-Z0-9_-]{1,64}$` rejects whitespace): `list_files` (list a directory as a `Contents of <path>:` header + one `[d] name` / `[f] name` line per entry; `path` optional, default `.`), `read_files` (**multi-file** `filepaths: string[]`; one `--- File: <path> ---` block per file, in request order), and `get_tree` (a `├── `/`└── ` connector tree; `path` optional default `.`; `max_depth` optional default 2; `.git` listed but not recursed). Every tool **requires** a `reason` (round 021) — a wire-parity argument the loop echoes into the tool-loop log (see Agent tool loop); it is **not** a consent gate. `read_files` reads each requested file **whole** (no per-file cap), in request order, **stopping at an aggregate token bound** with a truncation marker and a **skip** marker naming any requested files it could not return; it keeps the **50 files/call** cap (over that → `Error: requested too many files (N). …`). `list_files`/`get_tree` are bounded by the same aggregate bound. **Round 024 retires the former fixed 100000-byte per-file cap and 1 MiB aggregate constant** — the bound is now the **tool resource contract** parameter (`max_output_tokens`; see the Tool resource contract row), so a large file is read as far as the model's window allows (resolving the round-021 fixed-cap defect; a file larger than the bound is truncated with a marker pointing to the shell for slices). It renders a binary file as `(Binary file, cannot display as text)` and a directory path as `ERROR: path is a directory, use list_files instead`; an unreadable path renders an inline `ERROR: …` block (a recoverable tool result). **No path/safety boundary** — no `SafePath`, no consent (a settled exclusion) (round 008; round 021 aligns the contracts with the reference) |
| Agent command tool (`execute_command`) | Go stdlib `os/exec` (`bash -c`) | Round 024: the first **execution** tool — runs the model's `command` string through **`bash -c`** (bash-first, POSIX-only; no Windows branch), so pipes/wildcards/redirection are native and **no `pipe_commands` tool** exists. **No security/consent gate** (a settled exclusion). A non-zero exit is a **successful** tool result carrying the exit status (loop continues; reference parity); the result is bounded to the effective `max_output_tokens`; a command exceeding the effective `timeout` is **terminated as a process group** (`SysProcAttr{Setpgid: true}` + `kill(-pgid, SIGKILL)`, with `cmd.WaitDelay` so an orphaned descendant cannot wedge the wait) and surfaced as a **timeout result** (a **nil-error** result carrying a fixed "stopped" marker — never the loop's `error: ` path; uniform across every tool, FR-018); the child is read through **bounded pipes** (`StdoutPipe`/`StderrPipe`, never a `cmd.Stdout` buffer, which `os/exec` reads to EOF); `reason` is required and echoed into the tool-loop log (round-022 shape). Optional `output_file`/`append` bind the child's `stdout`/`stderr` **directly to the file handle** (streamed to disk; no inline preview; the escape hatch for large output). The child's streams are **never** inherited from `os.Stdout`/`os.Stderr`, so `stdout` stays byte-exact |
| Tool resource contract (bounds) | Hand-written Go (loop-enforced) | Round 024: every agent tool exposes optional **`max_output_tokens`** + **`timeout`** params, resolved in **three tiers — default + param + ceiling** — and enforced centrally by the agent loop. The bound derives from the **effective budget** = `min(configured MAX_HISTORY_TOKENS, the active model's configured context window)` (the window from an optional per-model `MODELS.<model>.CONTEXT_WINDOW`; absent → the configured budget), so it tracks `min(MAX_HISTORY_TOKENS, the configured window)` — **model-tracking only when `CONTEXT_WINDOW` is set**; otherwise it tracks the configured budget (this fallback is stated honestly; #49's protection is therefore **config-gated**). Default `max_output_tokens` = `effectiveBudget ÷ 4`; ceiling = `effectiveBudget ÷ 2` (a headroom reservation — one result cannot fill the window); the resolved bound is realised as a **byte** budget via one **contract-owned** constant (`bytesPerToken = 4`, a new separately-named constant — *not* the token estimator's ratio), i.e. **default `1000000 B`** at the shipped 1 M budget (replacing — not identical to — the round-021 fixed `1 MiB = 1048576 B`; the loop clamps on raw byte length, never the estimator). `timeout` default is per-tool (shell **300 s**, readers **30 s**; ceiling **7200 s**). Over-ceiling params are **clamped, never rejected**; **every** tool bounds its own output **at the source** (the loop clamp is the backstop); no new failure class |
| Agent tool loop | Hand-written Go (no framework) | Drive a bounded think→act→observe cycle inside one turn: send the conversation, execute any requested tools, feed their results back, and repeat until a final answer or the bound. Bound **`MAX_TOOL_LOOP`** (default **1000**, env/config override); each tool execution has a per-tool timeout. The loop is a sequence of **complete** provider calls — **not** streaming. Live tool-loop logs are written to `stderr` (round 008); **round 022** prints each call as a single timestamped line `[HH:MM:SS] [Tool] <tool name> - <reason>` when the call states a reason, else `[HH:MM:SS] [Tool] <tool name>` — the round-008/021 raw `arguments`/`result` segments are **not** echoed (an **operator-chosen** shape: the reference instead decomposes tool activity into `[Tool Engine]`/`[Tool Reason]`/`[Tool Action]`/`[Tool Result]` lines) — and, on a tool-using turn (≥1 tool log line), emits **one blank line** before the answer; the timestamp comes from the injected clock seam. Implemented as an `AgentLoop` orchestrator (a new `internal/agent` package), not inlined in the CLI; the `Tool` port carries a `context.Context` and each execution gets a per-tool timeout (RF-1 / RF-2). Round 014 records each executed step's provider **signature** alongside its result, so a resumed replay carries it. Round 019 adds a **`LoopObserver` hook seam** (`internal/domain/agent/`) — the loop invokes `OnInferenceStart/End`, `OnToolsStart/End`, and `Before/AfterToolLog` around its `Complete` calls and its `logStep` stderr write, so the CLI-injected spinner can label / clear / restore per phase. Round 024 makes the loop the single **enforcement point of the tool resource contract** (see that row): it resolves each call's effective bound/timeout, applies `context.WithTimeout`, and clamps the returned result by **raw byte length** against the byte budget the tool also bounds to at the source (the `Tool` port is widened two-way — an upward per-tool default descriptor plus the downward byte budget on `Execute`) |
| Token estimator | Go stdlib (hand-written heuristic) | A deterministic, offline estimate of the **wire payload** — the persona message, the tool declarations, and the conversation messages — used by the pre-flight status line; dependency-free — no BPE tokenizer (round 009; **inputs widened** in round 011 so the estimate is comparable to the provider's measured count) |
| Payload status line | Hand-written Go (no framework) | Per-turn payload-budget visibility on the **diagnostic stream (`stderr`)**: a pre-flight estimate `[HH:MM:SS] Payload: ~<est>/<budget> tokens - <mode> - <model>` — computed over the **wire payload** (persona message + tool declarations + messages, round 011) — before the provider request, and a post-turn actual `[HH:MM:SS] Payload: <actual>/<budget> tokens - <mode> - <model>` after it (the actual read from the provider's reported usage). Always-on — **not** TTY-gated and **not** suppressed by `-r`; carries **no** `tellme:` prefix (the class-phrase vocabulary is unchanged); the timestamp comes from an injectable clock seam. Observe-only: it never triggers pruning (round 009) |
| Turn chrome (operator) | Hand-written Go (`internal/ui`, no framework) | Round 017: the **non-TUI prompt surfaces** reproduce `tell-me-go`'s per-turn operator chrome on the **diagnostic stream (`stderr`)** — the acknowledgement `[HH:MM:SS] Input captured. Processing...`, a leading blank line, an **80-column** `─` rule, a `╭─⠿ Turn <N> - <mode>` header (`<N>` = the session's **completed-turn count** + 1 — one `history_entry` line per completed turn), the round-009 pre-flight payload line (text unchanged), and a trailing blank line, all before the answer. Emitted on the positional/piped prompt turn, the round-012 interactive plain reader, **and — round 023 — the `-i` submit surface**; every non-prompt path (boot / `-d` / `-l` / `--version` / prompt-less `--new`) is unchanged, and `stdout` stays byte-exact. **Round 023**: on the `-i` submit surface the submitted (trimmed) prompt is **echoed** on `stderr` immediately **before** the input-capture acknowledgement (the editor box that held it was cleared on submit), while the positional / Ctrl+D surfaces do **not** echo (their text is already on screen). Plain text — no ANSI colour this round (round-017 Decision 3); the timestamps come from the injected clock seam |
| Post-turn status lines (operator) | Hand-written Go (`internal/ui`, no framework) + a per-mode usage log | Round 018: after the answer, the **prompt surfaces** report `tell-me-go`'s post-turn status on the **diagnostic stream (`stderr`)** — a **metrics line** `[HH:MM:SS] [<provider>] M: <miss> H: <cached> C: <completion> Th: <thinking>` (from the API call that just returned; `Th:` **always** shown, incl. 0 — an operator decision deviating from the reference's suppress-when-0) and a **`╰─⠿ Ready` summary** `($<lastCall> $<turn> $<session> - M: … H: … O: … - <hit%>%)` (session-cumulative token totals + cache-hit rate; costs `$%.4f`, hit `%.1f%%`). Costs come from a **config-only** `MODELS` pricing table (no built-in rates; an un-priced model → `$0.0000`). Per-call usage is persisted to `output/<mode>/tokens.log`. Plain text (no ANSI); both lines are suppressed only when the provider reports no usage; `stdout` stays byte-exact |
| Turn progress spinner (operator) | Hand-written Go (`internal/ui`, no framework) | Round 019: the **non-TUI prompt surfaces** show `tell-me-go`'s **live progress spinner** on the **diagnostic stream (`stderr`)** so a run is never silently waiting — braille frames (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`) advancing on a ~200 ms injected ticker, drawn as `{frame}{status} ({elapsed}s)` with a carriage-return redraw (first frame synchronous; cleared with no trailing newline) — the `({elapsed}s)` counter is **turn-scoped** (counts from prompt capture and is never reset across interleaved waits). The **status label tracks the waiting phase**: ` Thinking [<model>]...` while awaiting the model, ` Executing [<tool>]...` / ` Executing tools [<a>, <b>]...` while tools run; the **tool-execution** state also shows the host CPU and memory percentages that the reference renders as a bracketed `CPU`/`MEM` segment. The spinner runs only when **the diagnostic stream (`stderr`) is a terminal and `-r` is off** (the diagnostic-stream gate — see Terminal detection) **and** the surface is a prompt-bearing turn (positional / piped / the round-012 reader / **the round-023 `-i` submit surface**); every non-prompt path is unchanged; `stdout` stays byte-exact; POSIX-only (Linux/macOS); no new dependency; the presenter serializes every frame and every `stderr` write through one I/O mutex, and `Stop()`/`Clear()` are synchronous (no in-flight frame survives a clear) |
| System metrics provider (telemetry) | Hand-written Go — a domain port (`internal/domain/metrics`) + infrastructure adapters under `internal/infrastructure/telemetry/` (build-tagged `system_metrics_linux.go` / `system_metrics_darwin.go`) | Round 019: **machine-wide** host CPU (Δ of `Σcpu − idle`; the `idle` column only — reference parity) and memory percentages for the spinner's tool-execution resource segment; dependency-free (stdlib `/proc` on Linux, `syscall` on macOS); injected behind the port so `internal/ui` stays a pure formatter package. The macOS **CPU** leg is **pending a cgo `mach` `host_statistics` sampler** and reports `0.0%` until it lands (a recorded forward item; this matches only the reference's *nocgo* path — its default **cgo** build does report macOS host CPU); the macOS memory leg uses `sysctl` over the free + speculative + purgeable page set. |

### Reasoning & Provider Transport

| Category | Technology | Purpose |
| --- | --- | --- |
| Provider gateway port | `internal/domain/llm` (`Gateway` interface + `Request`/`Response`/`ProviderError` value types) | Domain-facing, network-free provider abstraction; single method `Complete(ctx, Request) (Response, error)` so the transport is swappable and the turn is fake-testable.

| Write filesystem tools | Go stdlib (`os`, `path/filepath`, `strings`, `encoding/json`) | Round 029: two write tools on the same `domain/tools.Tool` port — `write_file(filepath, content, reason)` is **create-only**: it creates `filepath` with exactly `content` (mode **`0644`**), **refuses to overwrite an existing file**, creates missing parent directories (mode **`0755`**), and writes **atomically** (a temp file in the target directory is moved into place with an **atomic create-only** move — `os.Link`/`EEXIST` — so an existing file is never clobbered and the destination is never a partial file, with **no `Stat`/`rename` TOCTOU window**); `replace_text(filepath, old_text, new_text, reason)` is **strict-unique**: it replaces the block only when `old_text` occurs **exactly once**, and fails (leaving the file untouched) on **0** or **>1** matches, with its **write also atomic** (read → replace in memory → temp + `rename`); a no-op replace (`new_text` == `old_text`) short-circuits without a write; an empty `old_text`, a missing/unreadable file, or a create over an existing file is a recoverable **tool error** (the loop's non-terminal `error: …` result, never the frozen request-level phrase). **No security/consent gate and no backup/undo** (settled exclusions) — the write surface is deliberately the pair the shell cannot do reliably (`>` clobbers; `sed` miscarries on 0/multiple matches). `append_text` / `undo_file_change` stay deferred (`>>` / `git`); `delete_path` / `create_directory` are **non-goals** (`rm` / `mkdir -p`). Both tools require `reason`, honour the round-024 resource contract (30 s default timeout, FR-018 nil-error timeout result), and are stdlib-only / POSIX-only. **Recorded hazard:** `replace_text` reads the **whole** file to locate the unique block — the contract bounds the tool's **result**, not its **input**; a future input bound (or an anchored matcher) is a forward item. A **missing** `content` key is a recoverable error (only an explicit `""` writes an empty file); missing parent directories are created with mode `0755`. The provider-side guard against a transport silently truncating **large** tool arguments is delivered in **round 030** (see the Provider output-cap truncation guard row). |
| Agent command tool (`execute_command`) | Go stdlib `os/exec` (`bash -c`) | Round 024: the first **execution** tool — runs the model's `command` string through **`bash -c`** (bash-first, POSIX-only; no Windows branch), so pipes/wildcards/redirection are native and **no `pipe_commands` tool** exists. **No security/consent gate** (a settled exclusion). A non-zero exit is a **successful** tool result carrying the exit status (loop continues; reference parity); the result is bounded to the effective `max_output_tokens`; a command exceeding the effective `timeout` is **terminated as a process group** (`SysProcAttr{Setpgid: true}` + `kill(-pgid, SIGKILL)`, with `cmd.WaitDelay` so an orphaned descendant cannot wedge the wait) and surfaced as a **timeout result** (a **nil-error** result carrying a fixed "stopped" marker — never the loop's `error: ` path; uniform across every tool, FR-018); the child is read through **bounded pipes** (`StdoutPipe`/`StderrPipe`, never a `cmd.Stdout` buffer, which `os/exec` reads to EOF); `reason` is required and echoed into the tool-loop log (round-022 shape). Optional `output_file`/`append` bind the child's `stdout`/`stderr` **directly to the file handle** (streamed to disk; no inline preview; the escape hatch for large output). The child's streams are **never** inherited from `os.Stdout`/`os.Stderr`, so `stdout` stays byte-exact. **Round 034:** the child's stdout/stderr are also teed (both pipes, one line-assembly mutex) to a per-line `[Tool Output]` sink and streamed to `stderr` as `[HH:MM:SS] [Tool Output] <line>` lines bracketed by an `Executing... (Output shown below)` header + a fixed separator — but **only** for a call that does **not** carry `output_file` (which emits no block; `runToFile` binds the streams to the file handle); the stream is bounded by the round-024 byte budget and the bound is a **stop** (the process group is killed on overflow; `trimmed` + `TruncationMarker`), a trailing partial line is **dropped**, and the spinner is yielded **once per call** (single writer). **Round 038 (issue #78):** the streamed `[Tool Output]` **content** lines are **sanitized at the `internal/ui` presentation seam** — every **7-bit** terminal control sequence (ANSI escape: CSI/SGR, OSC, and any other ESC-introduced sequence) and every stray C0/DEL control character is **removed** (TAB kept; interior CR dropped, so in-place `\r` progress concatenates; the **8-bit C1** range and all other bytes `≥ 0x80` are untouched; the ESC consumption is ASCII-gated and the scan window is bounded **per kind** — CSI 128 / OSC 1024 — so a long **terminated** sequence (an OSC title or an OSC-8 hyperlink URL) is still removed in full while an unterminated one cannot swallow the line, and the sanitizer **never introduces** invalid UTF-8 — forwarded bytes pass through verbatim) — so a colouring/killing command can no longer tint or alter the operator's terminal for the rest of the run; the sanitization is **presentation-only** (the tool **result** fed to the model keeps its raw bytes). Independently, the block **always closes in a neutral state**: a single default-state restore (`\x1b[0m`) is written before the closing separator on every close path (normal, start failure, and the trim/timeout abort) — **unconditionally**, including on a non-terminal `stderr` (ADR 0007 D4; a visual no-op on a redirected stream). **Recorded divergence:** the reference has **no** output sanitizer (it forwards the same bytes). **Round 039 (issue #80):** this control-sanitization policy is generalized into a **single-owned** `internal/ui` rule (`sanitize.go`) applied by **every** `[Tool …]` formatter — the sibling `[Tool Reason]`/`[Tool Result]`/`[Tool Action]` values are now control-free too (see the Agent tool loop row). Full policy: **ADR 0008** (`docs/decisions/0008-terminal-safe-lines-and-blank-line-grouping.md`, which **supersedes** ADR 0007). |
| Agent tool schemas | Hand-written Go (stdlib `encoding/json`; shared schema builder) | Every agent tool advertises a JSON argument schema. The **shared schema builder** (`resourceSchema`) declares the resource params (`max_output_tokens`, `timeout`) **and the mandatory `reason` property**, so each tool it backs (`list_files`, `read_files`, `get_tree`, `write_file`, `replace_text`, `list_skills`) satisfies **`required ⊆ properties`** (round 031 — fixes issue #64: a strict provider such as Vertex/Gemini rejects the *whole* request when any tool's `required` names a property its `properties` never declares, so the defect only surfaced on Vertex, never on the tolerating OpenAI-compatible family). `execute_command` builds its schema inline and already declares `reason` (the lone pre-round-031 compliant tool). The defect was introduced by the shared builder at round-024 fold `cfa005c` (the prior inline schemas declared `reason`; the builder dropped it while callers kept passing it as required) and carried forward by round-029 fold `eb0367c`. stdlib-only; POSIX-only. |
| Tool resource contract (bounds) | Hand-written Go (loop-enforced) | Round 024: every agent tool exposes optional **`max_output_tokens`** + **`timeout`** params, resolved in **three tiers — default + param + ceiling** — and enforced centrally by the agent loop. The bound derives from the **effective budget** = `min(configured MAX_HISTORY_TOKENS, the active model's configured context window)` (the window from an optional per-model `MODELS.<model>.CONTEXT_WINDOW`; absent → the configured budget), so it tracks `min(MAX_HISTORY_TOKENS, the configured window)` — **model-tracking only when `CONTEXT_WINDOW` is set**; otherwise it tracks the configured budget (this fallback is stated honestly; #49's protection is therefore **config-gated**). Default `max_output_tokens` = `effectiveBudget ÷ 4`; ceiling = `effectiveBudget ÷ 2` (a headroom reservation — one result cannot fill the window); the resolved bound is realised as a **byte** budget via one **contract-owned** constant (`bytesPerToken = 4`, a new separately-named constant — *not* the token estimator's ratio), i.e. **default `1000000 B`** at the shipped 1 M budget (replacing — not identical to — the round-021 fixed `1 MiB = 1048576 B`; the loop clamps on raw byte length, never the estimator). `timeout` default is per-tool (shell **300 s**, readers **30 s**; ceiling **7200 s**). Over-ceiling params are **clamped, never rejected**; **every** tool bounds its own output **at the source** (the loop clamp is the backstop); no new failure class |
| Agent tool loop | Hand-written Go (no framework) | Drive a bounded think→act→observe cycle inside one turn: send the conversation, execute any requested tools, feed their results back, and repeat until a final answer or the bound. Bound **`MAX_TOOL_LOOP`** (default **1000**, env/config override); each tool execution has a per-tool timeout. The loop is a sequence of **complete** provider calls — **not** streaming. Live tool-loop logs are written to `stderr` (round 008). **Round 034** reshapes them to the reference's decomposed rendering (reversing round 022's operator-chosen single line): `[HH:MM:SS] [Tool Engine] Step i/M` once per **executed** tool round (at the execution site; `i`,`M` in executed-round units, `1 ≤ i ≤ M` by construction — the bound-reached call renders no engine line); per call `[HH:MM:SS] [Tool Reason] <reason>` — **round 036** folds (`\n`/`\r` → space) + trims the model-authored reason and caps it at **200 rendered runes** (one U+2026 counted inside the cap, rune-safe, evaluated on the folded value), exactly like the result snippet, and emits **no** reason line when the folded reason is blank (empty/whitespace-only) — restoring round-022 **B1**'s fold guarantee that round 034 dropped **unrecorded** (recorded now in **ADR 0006**); the cap set grows from `{189, 200}` to `{189, 200, 200}` — then `[HH:MM:SS] [Tool Action] <tool>(<args>)` (the `reason` key excluded; the remaining keys **sanitized, then sorted ascending**; each rendered **value** rune-capped at **189 rendered runes** — one U+2026 counted inside the cap, rune-boundary cut; values rendered from a `UseNumber()` decode — raw numeric literal, never `1e+06`; argument **keys** are sanitized but remain **uncapped**, and the joined list is not capped — the round-034 "whole list capped" wording was an editorial slip, corrected round 039); per call `[HH:MM:SS] [Tool Result] <tool>: <snippet>` (folded, capped at **200 rendered runes**, one U+2026, rune-safe); a live `[HH:MM:SS] [Tool Output]` block for a shell-class call **without** `output_file`; and the round's reasons re-emitted **grouped** at each call's post-call tail. Round 022's single-line shape, its no-reason branch, and its one-blank-line-before-the-answer rule are **superseded**. Timestamps come from the injected clock seam; the block is produced by the CLI via two loop observer seams — call-begin `(callIndex, messages []llm.Message)` and call-end `(callIndex, usage, roundReasons, final)` (`usage.PromptTokens` *is* the measured payload; the CLI observer computes `llm.EstimatePayload(person, toolDefs, messages)`) — `internal/agent` stays persona/pricing/store-free and carries no estimator field. **Divergences from the reference (recorded):** rune-safe caps + one U+2026 vs byte slices + three ASCII dots; sorted keys + `json.Number` vs map iteration + `%v`. Implemented as an `AgentLoop` orchestrator (a new `internal/agent` package), not inlined in the CLI; the `Tool` port carries a `context.Context` and each execution gets a per-tool timeout (RF-1 / RF-2). Round 014 records each executed step's provider **signature** alongside its result, so a resumed replay carries it.

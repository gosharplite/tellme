## Last delivered round - 072 `072-gemini-cached-token-usage` (DELIVERED / FROZEN - PR [#150](https://github.com/gosharplite/tellme/pull/150) merged into `dev` `6c3e5fe`, **merge commit**; **ADR 0044**)

- **Theme**: fix a **cost/accounting bug** — the Gemini/Vertex adapter decoded only 3 of the response's `usageMetadata` fields, so `llm.Usage.CachedTokens` stayed 0 and, downstream (`miss = prompt − cached`), the **whole prompt** was billed at the **MISS** rate on every Gemini turn (`gemini-3.8-flash`: MISS is **10×** HIT) — a silent over-charge of up to ~10× the input rate, with `H: 0` always. Anchor bug [#149](https://github.com/gosharplite/tellme/issues/149) (**closes it**). The fix: decode **`cachedContentTokenCount` → `Usage.CachedTokens`** and **`thoughtsTokenCount` → `Usage.ThinkingTokens`**, each floored at 0 and the cached count **capped at the prompt** (so the miss is never negative / the hit-rate never exceeds 100%). The **disjointness is family-specific**: Gemini's `candidatesTokenCount` **excludes** thoughts (no subtraction), unlike the OpenAI-compatible adapter (whose `completion_tokens` includes reasoning and is stored exclusive). **Clarify not escalated (0 questions)**.
- **The change**: `internal/infrastructure/llm/gemini/client.go` — the `usageMetadata` decode struct gains the two fields and the `llm.Usage` mapping sets them. **Family-local**: the request body, the emitted turn, and the OpenAI-compatible wire are byte-identical; the cost formula (`ComputeCost`/`miss`) is reused unchanged.
